# Мониторинг здоровья школьника (Android)

Приложение для сбора 11 анкет мониторинга здоровья школьников с двумя типами входа (родитель / сотрудник школы) и выгрузкой результатов в **XLSX по официальным макетам** и **PDF**.

## Как это работает

- **Родитель** входит по коду приглашения класса (демо-код: `36KEM-5A`), создаёт карточку ребёнка (три буквы ФИО + дата рождения + пол — полные ФИО не хранятся) и заполняет 7 «домашних» анкет: №4, 5, 6, 9, 10 и «детские» №7, 8.
- **Сотрудник школы** входит по логину/паролю (демо: `admin` / `admin`). Классный руководитель заполняет №11, медработник — №1 и №2, физрук — №3, администратор видит всё.
- **Выгрузка**: по кнопке формируются XLSX (лист «данные», строка 1 — коды полей `region, school, grade, class, name1, ..., height, weight, ...`, строка 2 — русские подписи, далее строки на каждого ребёнка — точно как в ваших макетах) и PDF по каждому ребёнку.

Все данные хранятся локально на устройстве в JSON. Синхронизация между устройствами родителей и учителя в этой версии не входит (следующий этап — бэкенд).

## Сборка через GitHub

1. Создайте пустой репозиторий на GitHub.
2. Залейте туда содержимое этой папки (`git init`, `git add .`, `git commit`, `git remote add origin ...`, `git push`).
3. Actions запустится автоматически (workflow `Build Android APK`). Через ~5–7 минут в разделе **Actions → последний запуск → Artifacts** появится `HealthMonitor-debug-apk.zip` со сборкой.
4. Скачайте, распакуйте, установите APK на Android-устройство (в настройках разрешить установку из неизвестных источников).

Минимальная поддерживаемая версия Android — 7.0 (API 24).

## Локальная сборка (опционально)

Требуется JDK 17 и Android SDK.

```bash
gradle wrapper --gradle-version 8.9
./gradlew :app:assembleDebug
```

APK будет в `app/build/outputs/apk/debug/`.

## Как расширить

Добавить/изменить вопросы в анкете — правьте `AnketaCatalog.kt`. Форма и выгрузка подхватят автоматически, потому что рендер и экспорт работают по схеме `Field`.

Коды полей выгрузки (`height`, `weight`, `run30`, `score` и т.д.) совпадают со строкой 1 ваших исходных `.xlsx`-макетов из архива Kemerovo_MAOU_SOSh_36 — импорт в стороннюю систему сработает без правок.

## Следующие шаги (рекомендация)

1. **Синхронизация**. Сейчас данные только локальные — каждый родитель фактически ведёт свою копию. Реальному классу нужен общий сервер. Самый быстрый вариант — Supabase (PostgreSQL + аутентификация + row-level security «родитель видит только своего ребёнка»). Хранение на серверах в РФ — Yandex Cloud / Selectel + свой backend на Ktor или FastAPI.
2. **Настоящая безопасность**. Пароли учителей — хешировать (bcrypt). Токены — JWT. Передача — только HTTPS.
3. **Офлайн-первый режим** — заполнение локально, синхронизация при появлении сети (Room + WorkManager).
4. **iOS** — если понадобится, разумно переписать на Kotlin Multiplatform (сохранив логику `domain/` и `export/`) или на Flutter.
5. **Push-напоминания** родителям («до окончания сбора — 3 дня, осталось 2 анкеты»).
